# 使用示例（examples.md）

> 三个典型场景，展示「触发 → 执行 → 产出」全链路，帮助新使用者快速上手。

## 示例 1：把已有 Word 改成反馈回复样式（最常用）

**用户触发**：「把这个 docx 按反馈回复样式改一下」

**执行链路**：
1. S1 识别：用户明确 → 反馈回复版
2. S2 加载：确认 `assets/templates/反馈回复样式.docx` 存在
3. S3 路由：已有文件整套套样式 → `minimax-docx apply-template --input 原文件.docx --template assets/templates/反馈回复样式.docx --output 输出.docx`
4. S4 映射：问题标题→0011、监管问题原文→001（黑体）、回复正文→000（首行缩进 2 字符 1.5 倍）、明细标题→002/003（加粗）、表格→a6 三线表
5. S5 规则：序号从「问题1.XXX」起，明细按「一、→（一）」；表格三线表
6. S6 校验：`check_styles.py --input 输出.docx --scenario 反馈回复` → PASS 交付
7. S7 声明：「已按反馈回复版样式套用（0011/001/000-009）」

**产出**：合规 docx + 校验报告（必备样式齐全/无裸段落/无空段落/标题连续）

## 示例 2：按招股书样式写一份分析报告（新建）

**用户触发**：「按招股书格式写一份项目分析报告」

**执行链路**：
1. S1 识别：正式文档 → 招股书版（000-009）
2. S2 加载：`assets/templates/报告模板.docx`
3. S3 路由：新建 → `tencent-docx` 创作（声明按 000-009 样式生成）；不可用则脚本兜底（以模板为基底组装 document.xml）
4. S4 映射：章标题→001（黑体 16pt 居中分页前）、节标题→002（黑体 14pt）、小节→003、正文→000、单位行→008、备注→009
5. S5 规则：一级用「一、」或自定义编号，二级「（一）」依九级链顺延
6. S6 校验：`--scenario 招股书` → PASS
7. S7 声明：「已按报告模板 000-009 样式生成」

**产出**：符合招股书版式的新 docx（内容需另行提供或来自专家分析）

## 示例 3：局部微调样式（改一段/改表格）

**用户触发**：「把这份回复的表格改成三线表，正文首行缩进」

**执行链路**：
1. S1 识别：局部调整 → 场景 C
2. S3 路由：`tencent-local-office-edit` 实时编辑（唯一编辑中枢）
3. 按 `style-map.md` / `rules.md` 应用：表格三线表（上下 1.5pt/内部 0.5pt、表头加粗居中、单元格垂直居中）、正文 000 样式
4. S6 校验：`check_styles.py` 确认无裸段落/无空段落
5. S7 声明：列出修改点清单

**产出**：原地保存的 docx + 修改点说明

## 失败降级示例（工具不可用时）

- `minimax-docx` 不可用 → **脚本兜底**：以 `assets/templates/反馈回复样式.docx` 为基底（复制 styles.xml/settings/numbering 等部件），仅替换 document.xml（段落 pStyle + 三线表）；交付注明「脚本兜底生成，封面/TOC/页眉页脚等复杂元素待人工处理」
- 文档含封面/TOC 等脚本覆盖不了的元素 → 输出 Markdown + 样式说明，建议走专业工具

## 模板自定义示例（改模板 = 改输出）

**用户需求**：所有反馈回复的正文字号从 12pt 改成 10.5pt

**操作**：用 Word 打开 `assets/templates/反馈回复样式.docx` → 修改样式「000正文（反馈回复）」字号为五号（10.5pt）→ 保存 → 重新运行 `check_styles.py --mode template` 校验样式库 → 之后所有按反馈回复版生成的文档自动跟随 10.5pt 正文

> 原理：脚本/工具组装时复制模板的 styles.xml，「模板即样式源」。
