# IPO 文档序号与表格规则（rules.md）

> 规则来源：用户 2026-08-13 裁定（标题序号链 + 序号前缀≠标题）+ 表格模板.docx 实证（三线表规范）+ 反馈回复模板 document.xml 实证（排版范式）+ 2026-08-25 裁定（段落间距靠样式 spacing 控制、禁止空段落）。

## 一、标题序号九级链

完整序号链：`一、 → （一） → 1、 → （1） → 1） → ① → A、 → a、`

| 层级 | 序号格式 | 示例 | 对应 pStyle |
|------|---------|------|------------|
| 一级 | 文档自定义编号 **或** `一、` | 反馈回复"问题1.XXX"；招股书"第一节 XXX"；无自定义编号文档用"一、" | 反馈回复版=0011；招股书版=001 |
| 二级 | `一、` | "一、主营业务与产品" | 002 |
| 三级 | `（一）` | "（一）行业基本情况" | 003 |
| 四级 | `1、` | "1、市场规模" | 004 |
| 五级 | `（1）` | "（1）竞争格局" | 005 |
| 六级 | `1）` | "1）可比公司" | 006 |
| 七级 | `①` | "① 收入构成" | 007 |
| 八级 | `A、` | "A、按产品拆分" | 正文加粗（超出标题层级） |
| 九级 | `a、` | "a、按区域拆分" | 正文加粗（超出标题层级） |

**核心规则**：
1. **反馈回复**：一级标题 = 自定义编号"问题1.XXX"（0011），二级标题序号从"一、"开始（002），三级从"（一）"开始（003），以此类推。
2. **招股书**：一级标题 = 自定义编号"第一节 XXX"（001），二级标题序号从"一、"开始（002），三级从"（一）"开始（003），以此类推。
3. **无自定义一级编号的文档**（备忘录/分析报告/尽调报告等）：一级直接用"一、"（对应 001），其后按表顺延。
4. 序号层级最多到九级（a、）；超出用（a）等变体或拆分表格，避免嵌套过深。
5. 样式映射：0011/001（一级/问题标题）→ 自定义编号；002 → "一、"；003 → "（一）"；004 → "1、"；005 → "（1）"；006 → "1）"；007 → "①"；更深层级用正文加粗（008/009 为表格专用，不承担标题）。

### ⚠️ 序号前缀≠标题（2026-08-13 用户裁定）

"1、""（1）""1）""①"开头的段落**可能是正文而非标题**，必须按文档前后结构判断：

| 情形 | 判定 | 用哪个样式 |
|------|------|-----------|
| 引导句+列举正文（"呈现以下特征：""来源于X个方面：""包括：""如下："后接长句完整论述、>40字、段后无独立正文展开） | 列举正文 | **000 正文** |
| 短标题+段后正文展开（≤40字冒号式短语、后跟独立正文段落） | 标题 | 对应标题样式（004/005/006/007） |

> 实证（超聚变案）："（1）全球算力基础设施市场规模快速提升。…""①工程化壁垒：…"均为列举正文 → 000，已修正。

## 二、表格三线表规范（表格模板.docx 内置示例表格实证 + 2026-08-25 用户裁定）

> **权威实证**：表格模板.docx 的 document.xml 内置完整示例表格（可比公司指标表，6 行 8 列，两行表头），以下规范全部来自该表格逐单元格解析。

### 表格级（tblPr）

| 要求 | 规范 | 模板实证 |
|------|------|---------|
| 表格宽度 | **页面 100% 宽，Word 自动调整**（用户裁定 2026-08-25） | `tblW w:w="5000" w:type="pct"`（5000 pct = 100%） |
| 表格对齐 | 水平居中 | `jc w:val="center"` |
| 上下框线 | **1.5pt 黑色实线**（sz=12） | tblBorders top/bottom sz=12 |
| 内部框线 | **0.5pt 黑色实线**（sz=4） | insideH/insideV sz=4 |
| 左右框线 | **不加**（三线表式） | left/right 无 |
| 边框颜色 | **纯黑 000000**（用户裁定 2026-08-25，弃模板原 010000） | color 000000 |
| 单元格边距 | 左右 57 dxa | `tblCellMar left/right=57` |
| 表格样式标记 | `tblLook w:val="04A0"`（firstRow/firstColumn 特殊处理） | tblLook 04A0 |
| 列定义 | 每列 gridCol 均分或按内容；Word 自动调整优先 | tblGrid（模板 8 列不等宽） |

### 行属性（trPr，每行必带）

| 要求 | 规范 | 模板实证 |
|------|------|---------|
| 禁止跨页拆行 | `cantSplit` | 每行均有 |
| 行高 | `trHeight w:val="397"`（约 0.7cm） | 每行 397 |
| 行对齐 | 居中 `jc w:val="center"` | 每行均 center |
| 表头行标记 | **多行表头每行都设 `tblHeader`**（跨页重复） | 行0/行1 tblHeader |

### 表头结构（支持复杂表头，用户裁定 2026-08-25）

| 能力 | 规范 | 模板实证 |
|------|------|---------|
| 两级表头 | 第一行组头（如年度「2026年度」跨列合并）+ 第二行子头（如「金额/占比」） | 行0（gridSpan=2 年度）+ 行1（金额/占比） |
| 跨列合并 | 组头单元格 `gridSpan`（值为占列数） | 年度 gridSpan=2 |
| 跨行合并 | 类别列（如「可比公司」）`vMerge restart` + 后续行 `vMerge continue` | 可比公司/项目 行0-1 vMerge |
| 表头格式 | **加粗 + 居中 + 10.5pt（sz=21）** | cell 均 bold+center+sz21 |

### 内容对齐细则（按模板固化，用户裁定 2026-08-25）

- **表头单元格** → 加粗 + 居中
- **首列/前几列文字**（类别/项目名）→ 左对齐（默认，不设 jc）
- **会计数字**（金额/百分比/数量）→ 右对齐（`pjc w:val="right"`）
- **合计行** → 「合计」标签跨列合并（gridSpan）+ **加粗**；数字右对齐 + 加粗
- 其余正文性内容 → 两端对齐

### 其他格式

| 要求 | 规范 | 模板实证 |
|------|------|---------|
| 字体 | 全表 **10.5pt（五号，sz=21）宋体 + Times New Roman** | 单元格 sz=21 |
| 垂直居中 | 单元格内所有段落**上下居中** | tcPr vAlign=center |

### 生成要求

- 表格按上表逐项设置（tblPr / trPr / 表头合并 / 对齐 / 字号 / 行高）；有模板示例结构可参考 `assets/templates/表格模板.docx`
- 禁止手写不一致边框（如只有部分框线、粗细不一）
- 简单表格（单行表头）与复杂表格（两级表头+合并）均适用本规范

## 三、通用排版铁律

1. **字体**：正文宋体小四（12pt）首行缩进2字符1.5倍行距；标题黑体（招股书版）或加粗（反馈回复版）
2. **数据**：保留两位小数，金额单位统一（亿元/万元），每个数字带时点+来源
3. **日期**：YYYY年MM月DD日 或 YYYY-MM-DD
4. **反馈回复双段式结构**：【发行人说明与披露】逐项编号四级标题＋【中介机构核查及说明】（核查程序逐项定义抽样标准+核查结论）——监管问题黑体、回复宋体本身是合规展示
5. **段落间禁止空行/空段落（2026-08-25 用户裁定）**：段落间距一律靠样式 spacing（段前/段后）控制，**不得插入无文字的空段落（空行）分隔段落**。原因：①空段落无 pStyle，破坏样式体系统一性（被裸段落检查命中）；②样式自带 spacing（如 000 正文 beforeLines=50/afterLines=50）已提供间距，空段落造成间距叠加、版面失控；③空段落可能破坏标题 keepNext 链与大纲结构。适用：正文与正文、正文与标题、标题与标题之间均不得有空行；换段直接另起一段并应用对应 pStyle。
6. **只改格式、严禁修改原文内容（2026-08-25 用户裁定，最高优先级）**：样式应用不得增、删、改、移任何文字内容（含表格内文字、标点、空格、数字、单位）。套用样式后用 `check_styles.py --verify-content <原文件>` 校验，文本逐字不一致即 FAIL。内容修改属内容层任务（ipo-write-response），本 skill 一律不做。
